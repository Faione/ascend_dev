# AscendC Sinh 算子设计实验报告

## 一、实验目标

设计一个 AscendC 逐元素 Sinh 算子。输入张量形状为 `8 × 2048`，数据类型为 `half`，输出形状和类型与输入相同。计算公式为：

\[
\sinh(x)=\frac{e^x-e^{-x}}{2}
\]

实验覆盖核间数据划分、GM 与片上存储之间的搬运、计算阶段的中间结果安排，以及队列和临时缓冲区的管理。

## 二、实验设计

### 数据划分

输入共 `8 × 2048 = 16384` 个元素。使用 8 个核时，每核处理连续的 2048 个元素。设置 `TILE_NUM = 8`、`BUFFER_NUM = 2`，每核循环 16 次，每轮处理 128 个 `half`：

```text
BLOCK_LENGTH = 16384 / 8 = 2048
TILE_LENGTH  = BLOCK_LENGTH / TILE_NUM / BUFFER_NUM
             = 2048 / 8 / 2 = 128
循环次数      = TILE_NUM × BUFFER_NUM = 16
```

`TILE_LENGTH` 是每轮搬运和计算的元素数。`BUFFER_NUM` 对应可交替使用的队列缓冲区数量；它参与当前分段公式，不表示重复计算。每核的 16 轮共覆盖 `16 × 128 = 2048` 个元素。

GM 张量在初始化时已偏移到当前核负责区域的起点，第 `i` 轮使用 `i × TILE_LENGTH` 作为元素偏移。

### 数据搬运

`CopyIn(i)` 从输入队列申请 `LocalTensor<half>`，使用 `DataCopyPad` 从 GM 搬入当前轮的 128 个元素，随后入队。一次搬运一个连续数据块，因此 `blockCount = 1`，`blockLen = TILE_LENGTH × sizeof(half) = 256` 字节。256 字节满足 32 字节对齐要求，此处无需左右填充。

`CopyOut(i)` 从输出队列取出计算结果，写回 GM 对应位置，然后释放队列张量。GM 张量下标按**元素**计；`DataCopyPad` 的 `blockLen` 按**字节**计。

### 计算与缓冲区

使用三地址码表示公式，可以分别标出每一步产生的结果及其最后一次使用位置。三地址码将复合表达式拆为简单语句，例如 `t = a + b`。Sinh 公式可拆为：

```text
t1 = -x
t2 = exp(t1)       // exp(-x)
t3 = exp(x)
t4 = t3 - t2
y  = t4 × 0.5
```

`t1` 在计算完 `t2` 后不再使用，其缓冲区可用于保存 `t3`。对应的片上数据安排如下：

```text
temp1  = -x
temp2  = exp(temp1)
temp1  = exp(x)
xLocal = temp1 - temp2
yLocal = xLocal × 0.5
```

计算可使用基础向量 API `Muls`、`Exp` 和 `Sub`。两次 `Exp` 的源和目的使用不同缓冲区；`Sub` 的输入顺序保持为 `exp(x) - exp(-x)`。缓冲区的复用还需满足具体 API 的地址重叠约束，不能只根据三地址码中的结果生命周期判断。

输入与输出张量由 `TQue` 管理，计算临时空间由 `TBuf` 管理。从 `TBuf.Get()` 取得的张量不调用队列的 `FreeTensor`；队列张量则按入队、出队和释放流程管理。缓冲区不会在复用时自动清零，因此每轮读取的 128 个元素必须已在该轮完整写入。连续基础向量运算中可见的 `LocalTensor` 依赖通常由编译器处理；搬运与计算阶段通过队列交接数据。

## 三、结果验证

Sinh 算子已通过真机验证。

## 四、经验总结

本实验把形状和核数落实为明确的搬运范围：每核 2048 个元素，每轮 128 个元素。检查搬运参数时，需要始终区分元素偏移与字节长度。

三地址码适合分析中间结果的生命周期，能够指出 `temp1` 的复用时机；实际覆盖是否安全仍取决于 AscendC 接口的地址约束。`TQue` 与 `TBuf` 的管理方式也不同：队列张量需要按队列流程释放，临时缓冲区则需要保证先写后读。
